# Phase 2 drills on Binance Demo Trading

Date: 2026-10-22 (UTC). Venue: Binance Demo Trading, USD-M futures (`demo-fapi.binance.com`).

Result: all drills pass. They found two defects that the simulated drills had missed; both are fixed, covered by new tests, and re-run on Demo Trading.

## Setup

- **Account size.** The demo account holds 5,000 USDT. The bot was shown a virtual account of 125 USDT, the size of the live account (`VirtualBalance`), so position sizes matched live trading. PnL flows one to one.
- **Risk configuration.** The live file `config/risk.toml`, not the drill file.
- **Loss-line and target scenarios.** These used `mb --env demo demo-shift`, which moves the virtual equity as if PnL happened elsewhere. The open-risk budget prevents stops alone from reaching the loss line, so the drills needed this shift.
- **Instrument.** SOLUSDT perpetual, around 107.4 USDT.

## Defects found and fixed

**A. The fill of a market order could not be parsed** (commit `f202147`).

- Demo Trading answers a MARKET order with `newOrderRespType=RESULT` without `avgPrice`.
- The entry raised after the order had filled, so the position had no stop.
- The reconciler closed it as an unknown position on the next tick, about 6 s later.
- Fix: the adapter queries the order when `avgPrice` is missing. Any failure after an entry order is sent now closes the position at once.

**B. A stop could not be moved** (commit `bc28d83`).

- Binance allows one close-position stop per direction (`-4130`). So "place the new stop, then cancel the old one" failed, and PROTECT could not tighten the stop.
- The old stop stayed in place, so the position was never unprotected.
- Fix: stops are now reduce-only STOP_MARKET orders for the position's quantity, and take-profits still close the whole position. The reconciler cancels reduce-only stops left behind after a position closes. The simulator now rejects a second close-position order like Binance.
